# 相補ツール — 熱力学発見 × 理想想像 × 必殺仕訳

> 散らかりの整理は1つのツールに押し込めず、3つの役割に分ける。
> 合体させると複雑化する。各ツールは **1ツール=1役割** に徹する。

| ツール | 役割 | 答えを出す問い | 出口 |
|---|---|---|---|
| 熱力学 entropy CLI（木村 / seiri-seiton） | 散らかりを**発見**する | いまどこが散らかってる? | S（散らかり度）・相（vapor/liquid/solid） |
| **bons.ai**（furui） | **理想状態を想像**する | どうあるべきか? | 4バケット（agent/skill/project/wiki）の棚図 |
| **jev**（仕訳人） | **必殺仕訳**する | これはどれに当たる? | choice で1件ずつ切って棚へ |

## 順番（仕組む流れ）

```
[発見] 木村  : measure.py で S と相を測る  → どこが散らかってる? が分かる
[想像] furui : manifest → 理想の棚（4バケット）を描く
[仕訳] jev   : classify（choice）で1件ずつ振り分ける
[実行] furui : plan → apply で棚へ置く
[確認] 木村  : 再度 measure して S が下がったか検証
```

- **発見**と**想像**で「あるべき姿」を決める
- **仕訳人**がそれを1件1件の実装する
- **検証**（再計測）で本当に下がったか確かめる

## 原則

- furui はあくまで「理想を描いて移動させる」分類ツール。
  温度・相・決定表のような熱力学判断は furui に入れない。
- 熱力学エントロピーは木村（seiri-seiton）側が所有する。
- 連携はドキュメント上の順番で行い、1ツールに寄せない。

## 問いの存在

> **コードやエージェントは問いを解決する存在である。**

ツールは「道具」ではなく、それぞれが固有の**問い**に答える存在。
名前（モノ）ではなく問い（コト）でツールを捉えると、
複雑に合体するのではなく、問いごとに1つずつ並ぶ。

| 存在 | 問い |
|---|---|
| 木村（熱力学 CLI） | いまどこが散らかってる? |
| bons.ai（furui） | どうあるべきか? |
| jev（仕訳人） | これはどれに当たる? |

新しいツールを足すときは、先に「どんな問いに答える存在か」を決めてから作る。
